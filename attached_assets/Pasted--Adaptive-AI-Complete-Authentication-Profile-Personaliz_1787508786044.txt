# Adaptive AI — Complete Authentication, Profile, Personalization & App-Wide Design System

Implement a complete, production-quality authentication flow, Profile & Settings section, personalized Home dashboard, accessibility features, and unified design system across the entire Adaptive AI app.

The final application should feel like **one cohesive, professional, intelligent, adaptive, and accessible AI product**, not a collection of separately designed screens.

---

# 1. FIRST: INSPECT THE EXISTING APP

Before making any changes:

* Inspect the existing project structure, navigation, authentication logic, database/backend configuration, components, theme/styles, and Home dashboard.
* Inspect how the authenticated user's information is currently stored and retrieved.
* Identify where the user's:

  * Name
  * Email
  * Profile photo
  * Authentication state
    are currently available.
* Reuse existing components, services, utilities, authentication logic, database configuration, and navigation wherever possible.
* Do NOT unnecessarily rewrite working functionality.
* Preserve all existing Home dashboard and application functionality.
* Identify the existing Adaptive AI branding and improve its consistency without destroying the current identity.
* Follow the existing project's architecture and coding conventions.
* Avoid creating duplicate components or duplicate authentication logic.

---

# 2. COMPLETE AUTHENTICATION FLOW

Implement/refine the following flow:

**Unauthenticated User**
→ Login / Registration

**Login**
→ Home Dashboard

**Registration**
→ Home Dashboard

**Forgot Password**
→ Email

**Authenticated User**

# 7. PERSONALIZED HOME GREETING

This is an important part of Adaptive AI's identity.

The Home dashboard must use the **authenticated user's profile information** to personalize the experience.

## Dynamic Greeting

Retrieve the user's name from the existing authenticated user/profile data.

Based on the user's local time, display:

### Morning

**"Good morning, Asad 👋"**

### Afternoon

**"Good afternoon, Asad 👋"**

### Evening

**"Good evening, Asad 👋"**

Use the actual user's name dynamically.

Do NOT hardcode "Asad" or any specific user's name.

For example:

If the user's profile name is:

**Ali**

show:

**"Good morning, Ali 👋"**

If the user's profile name is:

**Sara**

show:

**"Good morning, Sara 👋"**

## Fallback

If the user's name is unavailable, empty, or has not loaded yet:

Show:

**"Good morning 👋"**

or the appropriate time-based equivalent.

Never display:

* "Good morning, undefined"
* "Good morning, null"
* "Good morning, User"
* An empty comma such as "Good morning, 👋"

## Time-based logic

Use the user's local device time.

Suggested behavior:

* Morning → 5:00 AM–11:59 AM
* Afternoon → 12:00 PM–4:59 PM
* Evening → 5:00 PM–4:59 AM

Keep the greeting logic reusable so it can be used elsewhere in the application.

## Loading behavior

While profile information is loading:

* Do not show broken text.
* Show an appropriate skeleton/loading state or neutral greeting.
* Once the profile is available, update the greeting smoothly.

## Profile synchronization

If the user changes their name from:

**Profile → Edit Profile**

the Home dashboard greeting should automatically update.

Example:

Before:

**Good morning, Asad 👋**

User changes name to:

**Asadullah**

Home should then display:

**Good morning, Asadullah 👋**

Do not require the user to log out and log back in to see the updated name.

# 14. ACCESSIBILITY REQUIREMENTS

Treat accessibility as a core product feature.

## Touch targets

All interactive elements must have a minimum:

**44 × 44pt**

This includes:

* Buttons
* Links
* Icons
* Back buttons
* Profile avatar actions
* Password visibility controls
* Checkboxes
* Toggles
* Microphone controls
* Navigation items

## Labels

Every form field must have a persistent visible label above the input.

Never rely on placeholder text as the only label.

## Dynamic text

* Respect system font scaling.
* Support larger accessibility text sizes.
* Prevent text clipping and overlapping.
* Allow buttons and layouts to adapt to larger text.

## Contrast

Meet:

**WCAG AA — minimum 4.5:1 contrast for normal text.**

Do not rely on color alone for:

* Errors
* Warnings
* Selection
* Success states

## Screen readers

Provide meaningful accessibility labels/hints for:

* Buttons
* Inputs
* Links
* Icons
* Toggles
* Checkboxes
* Profile controls
* Voice-guided controls

# MOST IMPORTANT PRODUCT GOAL

The final result should feel like a **single polished Adaptive AI ecosystem**.

The complete user journey should feel seamless:

**Login → Home → Profile → Settings → Accessibility → Edit Profile → Home**

and:

**Login → Forgot Password → Confirmation → Login**

and:

**Login → Registration → Home**

The Home dashboard should feel genuinely personalized:

**"Good morning, Asad 👋"**

rather than simply:

**"Good morning"**

when the user's name is available.

The personalization must come from real authenticated profile data, not hardcoded values.

The product identity should communicate:

**AI + Adaptability + Accessibility + Personalization + Professionalism**

Prioritize:

**Clean + Modern + Trustworthy + Accessible + Intelligent + Personalized**

Avoid:

* Excessive gradients
* Excessive glassmorphism
* Too many colors
* Excessive shadows
* Decorative coral
* Generic template-like UI
* Overly futuristic effects
* Inconsistent spacing
* Inconsistent typography
* Inconsistent buttons or inputs
* Hardcoded user information

Do not merely make the screens functional.

Make the entire Adaptive AI app feel **production-ready, cohesive, accessible, modern, trustworthy, intelligent, and professionally designed.**
