## 2. LOGIN

The Login screen should accept:

```text
Email: demo@adaptiveai.com
Password: Demo@12345
```

When the credentials are correct:

**Login → Home Dashboard**

The user should be authenticated immediately using local/dummy state.

Do NOT make a real Firebase/API authentication request for this temporary development mode.

If the credentials are incorrect:

* Show the existing inline validation/error UI.
* Show a non-blocking error banner.
* Keep the entered email.
* Do not clear the email field.

Example:

**Invalid email or password. Please try again.**

---

## 3. REGISTRATION

For now, make Registration work with dummy/local authentication as well.

When the user completes the registration form successfully:

1. Validate:

   * Name
   * Email
   * Password
   * Confirm password
   * Terms & Privacy checkbox

2. Save the registered user's information to local app state/storage.

3. Immediately authenticate the user.

4. Navigate directly to:

**Home Dashboard**

Do NOT send the user back to Login after successful registration.

## 5. LOGIN AFTER REGISTRATION

If a user registers using a new email/password, store those credentials in local development storage so that the user can subsequently log out and log back in.

Example:

```text

Password: Test@123
Name: Asad
        ↓
Account created locally
        ↓
Home
        ↓
Logout
        ↓
Login
        ↓
asad@example.com + Test@123
        ↓
Home
```

The dummy/local authentication system should therefore support:

* Create account
* Login
* Logout
* Persist user session
* Retrieve current user
* Profile information
